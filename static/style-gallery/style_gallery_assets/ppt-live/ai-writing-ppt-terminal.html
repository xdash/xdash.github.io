02

为什么写书要「工程化」？

// 没有版本管理的写作 = 野路子编程

写代码的人不靠一口气聊到底——靠仓库、commit、状态文件。写书也该一样。公众号作者「忒修斯的船板」独立推导出：编程 Agent 能跑几百轮不出事，是因为有文件系统随时刷新状态；写作只能靠聊天记录，聊到后面近因效应一上来，模型就当墙头草。

解法→查状态 → 写正文 → 更新状态文档# 三步循环，把写作也变成有状态的工作流

04

选题 = 需求分析：第一性三问

README.md
$ question1: 不可替代价值 # 市面缺哪句只有你敢说的真话？ $ question2: 独家可清点素材 # 124 份访谈逐字稿？46 张案例卡？ $ question3: 读者行为改变 # 合上书当晚能照着做什么动作？ $ if [ 三问答不出 ]; then echo "项目锁死 Phase 0，严禁起草" fi

反例：我亲手毙掉 1.6 万字《首席叙事官》——自造新词，本土没有真金白银的岗位案例承接，全是 AI 假想推演。

05

素材 = 资源文件：A/B/C 分级

research/notes.md
A类 一手物证 # 完整逐字稿 / 财报底稿 / 当事人原话 → 才是骨肉 B类 二手编译 # 公众号转述 / 媒体综述 → 只许找线索 C类 概念百科 # 维基词条 / 概念定义 → 只搭框架 $ grep -r "同一篇原文被十家转载" sources/ # 结论：转述链相同 → 证据学上永远只算「单源」

引文必须过子串精确校验：模型借人之口润色金句，搜不到原句当场阻断。

06

锚点表 = 接口契约：让模型无法跑偏

research/anchors/04.md
A01 主体/时间/数字/原话 # 原文首句 + 文件:行号 A02 ...共 15–20 条去重锚点 C01 3 张五段式案例卡 R01 1 个反面案例 $ if [ 锚点 < 15 ]; then mv chapter state/parked.md fi # 凑不齐 → 关进停职区，绝不硬写

外加母章注册制：核心案例指定唯一母章，其余章节只许一句话回指——从根源消灭跨章复述。

07

起草 = 编码实现：IPO 管线 + Golden Copy

make-a-book
Input 锚点表 + 案例卡 + 风格指南 Process 骨架碰撞 + 人工批注（最贵 15 分钟） Output 单章初稿 → 精修 → 确立 Golden Copy # 后续每章强制挂载：Golden Copy + Anchors + 母章边界

选型是生死问题：推理型模型 4000 token 全耗思考链、正文 0 字符；非推理型给出 4660 字成稿。电机马力不够，齿轮雕出花也没用。

08

修订 = 代码评审：级联纪律 + CI/CD

check_chapter.py
$ ./check_chapter.py chapter-07.md ✓ hard: 弯引号=0 ✓ hard: 中英粘连=0 ✓ hard: 模具句 ≤5 ~ soft: 单句段 10%–55%（放宽呼吸） ~ soft: 无证据段 25%–40%（留白）

case-041 教训：指标异化成目标 = 古德哈特定律。让异构模型挑刺，别让写的人审自己的稿子。

出版 = 发布上线：三通道部署

1数字/开源先行= 最快 24h 上线，fde4.ai 开源攒口碑，反向吸引出版社重点立项
2正规纸书= 工业级手稿包 + 白盒台账，省 80% 审稿成本，拿 ISBN 背书
3POD 内训= 垂直高客单圈层，跳过书店退货盘剥，直接高毛利

POSSE: Publish on Own Site, Syndicate Elsewhere

永远不要把读者资产寄生在中心化算法平台上——最后一页留一扇通往你私有阵地的门。

上线不是终点，是运维开始：宣发=版本推广，读者反馈=issue 工单，加印=迭代发版。

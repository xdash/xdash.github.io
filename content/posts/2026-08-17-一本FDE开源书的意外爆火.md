> 摘要：16 天，4,000 个 star，零推广预算。这个实验的结果，出版社大概不会喜欢。

7 月 29 日，我在 Claude Code 的辅助下，写完了一本 20.6 万字的新「书」。它原本只是我拿来自学的材料，也是我尝试用 AI 长篇写作的样例。

第二天下午，我顺手把它上传到了 GitHub ——没走熟悉的出版社、没上电子书平台、全部免费开源。然后发了条 tweet，推荐了下。

（Repo 是：[https://github.com/xdash/FDE-the-Guidance-Book-of-Forward-Deployed-Engineer](https://github.com/xdash/FDE-the-Guidance-Book-of-Forward-Deployed-Engineer)）

结果，一周后，这个仓库的 star 就直接超过了 3,000，又过去一周，破了 4,000。我写这篇的时候，已经涨到了 4,104。

GitHub 上几万 star 的项目一抓一大把。但一个「纯中文的 markdown 文档」如此迅速地拿到这个 star 数还是蛮神奇的。

其实从仓库发布后发现 star 井喷当天，我就调了 Agent，全程记录真实增长曲线，大致数据是这样：

- 发布当天：262
- 第三天：929
- 第七天：3,361
- 峰值是 8 月 4 日，单日 851
- 第八天开始断崖下降，之后稳定在每天几十
- 第 16 天破 4,000，随后进入长尾

也就是说，82% 的 star 来自第一周，后面全是长尾。

看到这儿你大概在想：刷的吧？

我真没刷量、没买量，也没发红包求 star。所有的增长原点，几乎都可以归因到发布当天的那条 tweet，算是点燃了 X.com 上中文 AI 研究群体的好奇与关注——

![点燃增长的发布推文](/images/2026-08-17-fde-book/tweet.jpg)

眼见这个项目火了，就有不少人主动来加我，林子大了真是什么鸟都有。

比如有想把我免费提供的开源内容，挂到闲鱼上卖钱的——

![有人想把免费开源内容挂到闲鱼卖钱](/images/2026-08-17-fde-book/xianyu.jpg)

比如有想创业搞培训的，自己不研发，直接开口问我要课件——

![有人开口要课件去搞培训](/images/2026-08-17-fde-book/training.jpg)

再比如也了解到一些借 FDE 大搞回扣的——

![借 FDE 搞回扣的对话](/images/2026-08-17-fde-book/kickback.jpg)

……真是眼界大开。

当然，也收到一些和大佬的交流机会（比如巨头公司高层、上市公司领导、某部委前副司长等），以及合作邀约。大家对这本书的主题十分关注，也有一些好玩的东西在酝酿中了，暂且按下不表。

今天先通过这篇文章，简单复盘下这个项目的诞生和历程。

## 一、为什么直接免费开源在 Github

我开源的这本书，叫《前线部署工程师》，写的是 AI 时代的一个新岗位——Forward Deployed Engineer，简单说就是「怎么在客户现场把 AI 项目真正落地」。

它的潜在读者是谁？AI 从业者、工程师、想转型的职场人、有技术服务公司的小老板等。这群人工作日泡在哪个网站上？GitHub、X.com 最多。

我想通这一层之后，答案就简单了：与其等几个月才把纸质书摆进书店等读者偶遇，不如直接把它放在读者每天必刷的流量路径上。

这就是全文直接在 Github 免费开源的发心。

在传统渠道里，读者买完一本书，交易就结束了。在 GitHub，读者点一个 star，这一个动作同时是收藏、背书和转发——它会把这本书带进关注者的动态，还会把仓库顶上 Trending 榜单，而 Trending 是全站免费的流量位。

一个 star，就是一次带身份属性的转发。

而且，用 Github 来「出版」一本开源书，还有个纸质书绝对无法比拟的优势：我可以随时任意修改。

比如，书发出去的第二天，我就直接把书名从《前置部署工程师》改成《前线部署工程师》。

一字之差，真的重要吗？反正我是很咬文嚼字的。

这个「Frontier」究竟怎么翻译成中文，网上的译法很多。

- 有译作「前置」的，但我觉得这像是强调时间上的先后概念，但很多时候并没有绝对的时间分隔，咨询、部署、交付等动作往往是穿插交织的；
- 有译作「前沿」的，但我怕这像是传递技术层面的自我吹捧，而懂的人都知道，很多时候并不需要用上最尖端的 AI 技术来满足客户需求，过于先锋反而容易当先烈；
- 只有「前线」更能体现这个岗位身体力行、冲刺在业务第一线的那种通力合作的迫切感，以及跟 Palantir 这个发迹于军用项目的老大哥契合。于是我最终还是改了书名。

这种在 Github 上写完发现不对劲，还能随便改的自由度，比起传统纸质出版来说还是太方便了。但恐怕也没几个人像我这么吹毛求疵、为了一个不起眼的字而上演脑内互搏了吧。

## 二、好选题恰是命中了被掩藏的需求 + 搭建了合理的结构

海外一篇报告说，FDE 这个岗位的招聘需求一年涨了 7 倍。与此同时，大量 AI 项目正濒临泡沫破灭和需求证伪，真能做落地的人才又凤毛麟角。

我读了大量关于 FDE 的行业报告、新闻聚合、重点案例的解析，但就是感觉没人能把这事儿怎么落地，给彻底讲清楚。市场上不缺宏大叙事的报道，也不乏偏「世界观」的介绍，但真正亟需的是一份偏「方法论」的实战手册。

我在当初用 AI 辅助自己写这本书时，也一直不知道怎么谋篇布局，来囊括和分拣我想要看到的实战内容。

直到某天灵光一闪。

想起了十年前自己写的那本《增长黑客》，一度非常畅销，就是因为我精心设计了它的内容框架结构——将岗位职能拆解成不同环节，每个环节以大量案例为核心，来展示与延伸。

于是，我便照着那本书的骨架，让 AI 仿照它辅助规划出了手头这本新的 FDE 的骨架结构——赢得客户、激活部署、守住续约、扩大收入、规模化复制。

![《前线部署工程师》的章节结构](/images/2026-08-17-fde-book/book-structure.png)

五章刚好对应 FDE 交付的完整生命周期。再加上开篇的综述，和篇末的完整案例解剖。

这结构一出来，我就觉得稳了，实际自己读下来，感受也很好，是我想看到的那种。

看来能用 AI 搜集和撰写这事，如今不难。难的真的是对全盘的理解之后，对结构的精准把控与审核。掌握了合理的间架结构，内容的填充与拆解就可以更加游刃有余。庖丁解牛的含金量还在上升。

## 三、AI 持续迭代 + 给读者开 issue 核查

我有一套自己搭的 AI 系统，叫它「贾维斯」——近百个定时任务替我抓信息、做转写、盯数据、造技能等。另有一套叫 100X 的知识萃取系统，它把平时我读过的、聊过的东西拆成可调用的素材，转写、打标，沉淀到 Obsidian 为核心的知识管理系统（如果你关注过，应该知道我曾经将它们做成了两门课程分享，反馈很好）。

这次写这本 FDE 的书，就充分调动了这两套体系，完成了从挖掘素材、调校内容到打包部署的全过程。

不过也不是一蹴而就的。仅完成初稿当天，我就又前后改了九轮。比如把典型 AI 腔「不是 xxx 而是 xxx」给毙掉。

发布到 Github 之后，发现反馈很好，就又在那几天疯狂迭代。几天时间，版本号从 v1.0.5 一路发到了 v1.0.24（读到早期版本的早鸟读者们，对不住了，最初的阅读体验是比较差的，有很多佶屈聱牙的句子，越往后的版本读起来越顺畅）。

我还会根据读者提交的 PR、Issue 来对内容进行优化。我还发现有人第一时间帮我做出了越南语翻译的版本：

![读者自发制作的越南语翻译版](/images/2026-08-17-fde-book/vietnamese-translation.jpg)

这个过程中我对借助 AI 改稿又有了很多新的实践，也将过程全程保留下来，萃取成了几个 skills，以后还能接着用。

## 四、后知后觉的流量承接与服务

我为这个项目专门搭建的官网—— fde4.ai （意思是 FDE for AI）是第 13 天才上线的。

也就是说，star 爆发的第一周，我啥后手计划都没有（比如做个正经官网来介绍）。读者想要手机端阅读、想要更快的访问速度、想要 EPUB 版本...对不起，不存在的。

后来，一些读者通过我留下的微信，主动联系上来，还有人拿书的内容创建了课程网站、skills、精华概括版等。

渐渐地我发现，大家其实除了看书本身，还有更高阶的需求——像是学习更详尽更具体的课程，以及在同好的社群里交流。

尤其是许多来加微信的人，一上来就默认我是有群的，开口就希望加群。搞得我手足无措。

我被问得多了，就问了一下我的 AI Coach（我用自己的上下文，结合许多圣贤/大师/老板视角，做了一组给自己提意见建议的教练），它建议我——「你最近确实 build 太多了，要停一停，勇敢去卖吧」（大概就说这么个意思）。

于是，我强迫自己从建造中刹车，从 Vibe Coding 的快感中抽离，开始认真思考真实的市场信号和明确需求。

最终，我决定设置一个付费门槛来筛选确有高阶需求的社群朋友，并计划 8 月 26 日做一场 FDE 的专题直播课+录播，讲书里放不下的水下信息和一线实操（跟开源书的重合度小于 20%，只在这个群里分享）。

当然还有一些权益，就不在这里展开了，感兴趣的还是可以到官网看看：https://FDE4.ai （也是 Claude Code 帮我搭建在 Github Pages 上的）

目前还是早鸟阶段，预购有优惠的。

## 写在最后

回头看这半个月，我做的事情无非：找到了需求断层的选题，用 AI 管线生产内容，在自有平台吆喝，以及市场导向地缺什么补什么。

而对比传统出版，我深刻察觉到：GitHub 是我见过最被低估的出版渠道。许多「古典」时代的 GTM 策略，已经不奏效了，新的 AI 时代要有更原生、更有想象力、更豁得出去的玩法。

如果你也在尝试输出内容、建立 AI 时代的话语权，不妨试试用 Github。
